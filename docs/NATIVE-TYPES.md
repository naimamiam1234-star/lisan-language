# أنواع لسان الأصلية وربط C — 0.9 preview

المسار الأصلي يحوّل لسان إلى LLVM ثم تعليمات المعالج؛ لا يضم مفسّر اللغة في البرنامج الناتج. دعم المضيف المعلن لهذه الزيادة هو x86-64 على Linux وWindows، ولا تعني ملفات المضيف firmware للـ Arduino.

## الأنواع والدوال

| الصياغة | المعنى |
|---|---|
| `ص8`، `ص16`، `ص32`، `ص64` | صحيح بإشارة وبالعرض المحدد |
| `ط8`، `ط16`، `ط32`، `ط64` | صحيح دون إشارة |
| `ع32`، `ع64` | عدد عشري IEEE 754؛ `عدد` اسم بديل لـ `ع64` |
| `منطقي` | `صحيح` أو `خطأ` |
| `فراغ` | نتيجة دالة بلا قيمة |
| `مؤشر<ص32>` | عنوان قيمة من النوع المحدد |

```text
دالة مضروب(س: ص32): ص32 {
    إذا (س <= 1) { أرجع 1؛ }
    وإلا { أرجع س * مضروب(س - 1)؛ }
}
ليكن كبير: ط64 = 18446744073709551615؛
اطبع(كبير)؛
اطبع(مضروب(5))؛
```

تحتفظ الثوابت الصحيحة بأرقامها الأصلية؛ لا تمر `ط64` عبر f64. لا تحويل ضمني بين متغيرين مختلفي النوع؛ الثابت العددي يأخذ نوع السياق إن كان صالحًا. التحويل الصريح مثل `تحويل<ص32>(س)` يُفحص قبل التنفيذ للثوابت، وأثناء التنفيذ للقيم المتغيرة. التحويل من عشري إلى صحيح يحذف الجزء الكسري باتجاه الصفر ثم يتحقق من النطاق؛ لا يحدث التفاف صامت عند تجاوز السعة.

الدوال ذات التواقيع الصريحة تتطلب نوع كل معامل ونتيجة وتحقق جميع مسارات الإرجاع. تدعم الاستدعاء الذاتي والشروط والحلقات و`توقف` و`تابع` والمنطق قصير الدارة. تتحقق العمليات الصحيحة من تجاوز السعة والقسمة على صفر وحالة MIN/-1. تُرفض نتائج float غير المنتهية، وكذلك القيم غير المنتهية العابرة لحدود C.

البرنامج الخالي من الصياغة الجديدة يستمر في مسار native السابق الذي يدعم النصوص وقوائم الأرقام. وجود نوع صريح أو تصريح خارجي/تصدير في أي وحدة يختار واجهة الأنواع للبرنامج المدمج؛ هذه الواجهة تدعم القيم العددية والمنطقية والمؤشرات وطباعة النص الثابت، **ولا تدعم بعد النصوص المُدارة والمجموعات أو builtins القديمة العامة**. تصدر تشخيصًا عند استعمالها ولا تعود تلقائيًا إلى المفسّر.

## استدعاء C

```text
خارجي دالة جمع_سي(أ: ص32، ب: ص32): ص32 = "c_add"؛
غير_آمن { اطبع(جمع_سي(20، 22))؛ }
```

```sh
clang -c examples/ffi/adapter.c -o adapter.o
lisan --native examples/ffi/import.lsn --link adapter.o --output app
```

تُكرر `--link FILE` للملفات الكائنية أو الأرشيفات أو أغلفة C المناسبة للمضيف. يمكن استخدام `--library NAME` و`--library-path DIR` مع أسماء المكتبات كما تتوقعها سلسلة الأدوات. كل وسيط يمر منفصلًا دون shell. لا يكفي تطابق اسم المكتبة: يجب تطابق المعمارية وABI والتوقيع وإعدادات البناء.

الواجهة تدعم scalars والمؤشرات ونتيجة void. ليست ربطًا مباشرًا لأصناف C++ أو القوالب أو struct-by-value أو varargs أو callbacks. تحتاج مكتبة C++ غلاف `extern "C"` بتوقيع مدعوم، وقد تحتاج مكتبة C++ القياسية أثناء الربط. الأغلفة تستخدم سياسة استبقاء وملكية معلنة، ولا يُسمح لها بالاحتفاظ بعنوان متغير محلي بعد انتهاء اقتراضه.

## تصدير مكتبة من لسان

```text
صدّر دالة جمع(أ: ص32، ب: ص32): ص32 = "lisan_add" {
    أرجع أ + ب؛
}
```

```sh
lisan --emit-object examples/ffi/library.lsn --output library.o
clang examples/ffi/host.c library.o -o host
```

في Windows يمكن تسمية الناتج `library.obj`. يحتوي الملف الكائني تعليمات المعالج للمضيف، بلا `main`. تُرفض أوامر المستوى الأعلى في وضع المكتبة؛ توضع الوظائف في الدوال المصدّرة. إذا استخدم كود المكتبة الطباعة أو حراس التشغيل، فقد يحتاج مضيف Windows إلى `legacy_stdio_definitions.lib` عبر الرابط؛ يوفر مترجم لسان هذا الربط عند إنتاج تنفيذي بنفسه.

المؤشرات وعمليات `عنوان` و`تحميل` و`خزن` لها عقد منفصل في [MEMORY-POINTERS.md](MEMORY-POINTERS.md). ليست ضمانًا لصحة عنوان أجنبي عشوائي.

## أوامر التحقق

- `--check`: تحليل الاستيرادات والأنواع وقدرات توليد LLVM دون تشغيل Clang أو البرنامج؛ لا يثبت نجاح الربط.
- `--test`: بناء ملف آلة مؤقت وتشغيله ونقل حالته ومخرجاته. يحتاج Clang 15 أو أحدث وموصل النظام.
- `--emit-llvm`: إخراج LLVM بعد الفحص؛ يحمي ملف المصدر من الاستبدال.
- `--check-legacy` و`--test-legacy` و`--interpret` و`-e`: مسارات توافق قديمة واضحة.
- `--build`: تغليف قديم يضم المفسّر؛ لا يُحسب ضمن قبول المترجم الأصلي.

`LISAN_CLANG` يحدد مسار ملف Clang التنفيذي، ولا يمثل نص أمر shell. الناتج يُبنى في مجلد خاص ثم يُنشر بعد النجاح، مع بقاء الناتج السابق إذا فشل البناء.
