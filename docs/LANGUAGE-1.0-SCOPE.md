# نطاق لسان 1.0 وعقد القبول

حالة الوثيقة: مواصفة عمل مقترحة، الإصدار 0.1، بتاريخ 2026-10-20. خط الأساس الذي روجع: شيفرة لسان 0.8.0 قبل تغييرات هذه الجلسة. وجود بند في هذه الوثيقة لا يعني تنفيذه أو نجاح اختباره.

## معنى اكتمال 1.0

المقصود بـ«اكتمال 1.0» تنفيذ **كل بنود عقد الإصدار المحدد أدناه** على أهدافه المعلنة، مع أدلة قبول قابلة للإعادة. لا يعني ذلك وجود كل مكتبات لغات العالم أو دعم كل لوحات Arduino والمتصفحات. المكتبة القياسية، الحزم الخارجية، وربط العتاد والويب مشاريع ذات إصدارات ومصفوفات توافق مستقلة.

لسان لغة ذات صياغة عربية وملفات UTF-8، تنفذ برامجها الأساسية بترجمة مسبقة إلى شيفرة آلة. تبقى أسماء ABI ورموز الأدوات الخارجية كما تفرضها المنصة؛ تعريب واجهة اللغة لا يستلزم تغيير ABI أو كتابة الأرقام بغير السياسة المنشورة في [NUMBERS-AND-STYLE.md](NUMBERS-AND-STYLE.md).

## ما تثبته الشيفرة الحالية

| المجال | الموجود عند المراجعة | دليل الفحص وحدوده |
|---|---|---|
| الترجمة الأصلية | AST إلى LLVM IR ثم Clang؛ الافتراضي لملف `.lsn` يبني برنامجًا ولا يشغّله | `src/main.rs` و`src/native.rs`؛ وجود التنفيذ لا يثبت نجاحه على كل منصة |
| القيم الأصلية | عدد double، منطقي، نص، قائمة أرقام؛ الدوال بمعاملات ونتيجة رقمية | `docs/NATIVE-COMPILER.md` و`tests/native_extended.rs` |
| التفسير القديم | قيم ومكتبات أوسع من المسار الأصلي، ومنها القواميس والملفات | `src/runtime.rs` و`docs/SYNTAX.md`؛ ليس دليل قبول للترجمة الأصلية |
| الاختبارات | توجد اختبارات لتوليد IR وبناء وتشغيل برنامج أصلي | `tests/native.rs` و`tests/native_extended.rs`؛ هذا جرد اختبارات وليس تقرير نجاح جديد |
| المحرر | تمييز نحوي ومقاطع VS Code | `editors/vscode/README.md`؛ لا LSP أو مصحح أخطاء |
| الحزم والأهداف | لا مدير حزم أو تعهد دعم Arduino/المتصفح ضمن خط الأساس | مراجعة ملفات المصدر وقيود دليل المترجم |

يحتوي README على أقسام تاريخية تصف المفسّر و`--build` بجوار وصف المترجم الحديث. لا تُقرأ مكتبات القسم التاريخي بوصفها ميزات أصلية. تكون قائمة الدعم الأصلية الموثقة والمختبرة هي المرجع عند إعداد الإصدار.

## عقد اللغة المقترح لـ 1.0

كل المربعات التالية غير مؤشرة لأنها شروط إصدار مستقبلية، حتى عندما يوجد تنفيذ جزئي. لا تُؤشر إلا بإرفاق رقم التغيير، وأمر الاختبار، والهدف، والنتيجة.

### الصياغة والتحكم

- [ ] قواعد إصدار ثابتة للمعرّفات العربية، الهروب في النصوص، التعليقات، الفواصل، أسبقية العمليات وتجميعها؛ تحديد التعامل مع تطبيع Unicode والمحارف الملتبسة دون تغيير صامت للمعرّفات.
- [ ] تعريفات المتغيرات والإسناد والكتل والنطاق المعجمي؛ الاحتفاظ بمعنى `دع` و`ليكن` و`متغير` كمتغيرات قابلة للتغيير ما لم يُعلن تغيير متعمد.
- [ ] `إذا/وإلا`، `بينما/طالما`، `لكل`، `توقف`، `تابع`، `أرجع`، مع رفض استخدامها خارج سياقها الصحيح، وتنفيذ قصير الدارة للمنطق.
- [ ] مواصفة واختبارات لترتيب تقييم المعاملات، نطاق الحلقة، تعديل مجموعة أثناء تكرارها، المدى بنهايته المستبعدة وخطوته الموجبة والسالبة ورفض الخطوة صفر.

### نظام الأنواع والدوال

- [ ] مرحلة تحقق ساكن مشتركة بين الفحص وتوليد الشيفرة؛ لا رجوع تلقائي إلى المفسّر عند رفض نوع أو ميزة.
- [ ] عدد افتراضي f64 متوافق مع البرامج الحالية، ومنطقي ونص ونتيجة بلا قيمة، وقوائم متجانسة وقواميس ذات مفاتيح نصية وقيم متجانسة. القوائم المختلطة والقيم الديناميكية ليست شرطًا لـ 1.0؛ يصدر رفض عربي صريح لها.
- [ ] أعداد صحيحة موقعة وغير موقعة بعروض 8/16/32/64 وf32 للتحكم والربط، مع تحويلات صريحة وتحديد تجاوز السعة والقسمة على صفر والقيم غير المنتهية والتحويل من النص.
- [ ] معاملات ونتائج دوال لجميع أنواع 1.0، واستدعاء ذاتي، وتحقق عدد الوسائط ومسارات الإرجاع؛ تحديد تمثيل القيم المركبة وABI الداخلي.
- [ ] وصف واضح للفهرسة والتحقق من الحدود، المساواة ونسخ القوائم والقواميس وتمريرها. يُختار عقد واحد ويُختبر؛ اختلاف النسخ الحالي بين المفسّر والأصلي لا يُترك غامضًا.

لا تُشترط الأصناف أو الوراثة أو generics أو closures أو التزامن أو async لإصدار 1.0. إضافتها تحتاج مواصفة مستقلة؛ غيابها لا يُخفى بعبارة «نظام أنواع كامل».

### الوحدات والذاكرة والأخطاء

- [ ] استيراد ملفات ووحدات بأسماء واضحة، مع كشف الدورات وتعارض الأسماء وتثبيت قواعد المسارات والتصدير وعدم الاعتماد على مجلد تشغيل المستخدم.
- [ ] إدارة تلقائية موثقة لذاكرة النصوص والمجموعات والدوال: استراتيجية معلنة، وتحرير الموارد، ومعالجة فشل التخصيص. لا يكفي الاعتماد على انتهاء العملية لتحرير كل نص مؤقت.
- [ ] ملكية الموارد الخارجية منفصلة عن ذاكرة القيم؛ إغلاق الملفات ومسارات الخطأ محددة ومختبرة. اختبارات ضغط وأداة كشف تسرب/فساد ذاكرة على هدف مضيف معتمد.
- [ ] تشخيص عربي يتضمن الملف والسطر والعمود للخطأ المعجمي والنحوي والنوعي، وتحديد سياق أخطاء التشغيل دون انهيار غير معالج.
- [ ] عقد قابل للاستعمال لأخطاء العمليات المتوقعة، مثل عدم وجود ملف وفشل تحليل عدد؛ يحدد مواصفةً تمثيل النجاح/الفشل وطريقة معالجته قبل اعتماد صياغة جديدة. فشل `تحقق` يعطي حالة خروج غير صفرية.

### المكتبة القياسية وأدوات التطوير

- [ ] سجل API ثابت يحدد الأسماء العربية والتواقيع والآثار الجانبية والأخطاء والأهداف لكل دالة، مع اختبارات أصلية لكل مدخل.
- [ ] أساس المضيف: الطباعة، التحويلات، الرياضيات، النصوص UTF-8، القوائم، القواميس، المدى، والتحققات. تُحسم هل أطوال النصوص وفهارسها نقاط Unicode أم عناقيد كتابية؛ لا تُسمّى البايتات أحرفًا.
- [ ] ملفات المضيف: القراءة والكتابة بأخطاء وحدود موثقة. توثيق صلاحيات العملية؛ لا ادعاء بوجود عزل أمني. الشبكات وواجهات الرسوم وحزم العتاد خارج المكتبة الأساسية لـ 1.0.
- [ ] مدير حزم أولي محلي/Git بوصف حزمة وإصدار ومجال إصدار، وملف قفل يثبت المصدر والمراجعة/البصمة وشجرة الاعتمادات، وبناء قابل للإعادة ووضع offline للاعتمادات المخزنة. لا تُنفذ سكربتات تنزيل/بناء غير معلنة؛ سجل حزم عام ليس شرط الإصدار.
- [ ] CLI موحد للفحص والبناء والاختبار وإظهار الإصدار والأخطاء؛ صيغة ثابتة لحالات الخروج، وتوثيق اعتماد Clang والربط وقت البناء.
- [ ] إضافة VS Code قابلة للتثبيت، مع تمييز ومقاطع وLSP أولي للتشخيص والتعريف والإكمال من بيانات اللغة نفسها؛ اختبار العربية وRTL والمواضع متعددة البايتات. مصحح أخطاء تفاعلي ليس شرط 1.0.

## دلالات الأوامر: خط الأساس والهدف

| الأمر | معنى خط الأساس عند المراجعة | شرط القبول المقترح |
|---|---|---|
| `lisan ملف.lsn` | يبني ملفًا أصليًا باسم ساق الملف في مجلد التشغيل؛ لا يشغله | يبقى بناءً أصليًا موثقًا؛ الخطأ لا يستدعي المفسّر |
| `--native` | LLVM/Clang إلى ملف تنفيذي | تجميع وربط أصليان؛ لا شجرة AST أو مفسّر لغة مضمّن |
| `--emit-llvm` | إخراج LLVM IR | يفحص دلالات المسار الأصلي نفسه؛ إخراج IR لا يثبت نجاح الربط |
| `--check` | `check_file` يستدعي `modules::load_file` فقط | تحقق قواعد ووحدات وأنواع ودلالات الهدف الأصلي دون تشغيل البرنامج؛ لا يضمن توفر الموصل أو نجاح الربط |
| `--test` | ينفذ `Interpreter::run_file`؛ قد ينجح برنامج لا يقبله الأصلي | يبني ملفًا أصليًا مؤقتًا ويشغله، ويعيد فشل التحقق/التشغيل؛ لا نجاح معلن قبل نجاح العملية الناتجة |
| `--interpret` و`-e` | تشغيل المفسّر القديم | يبقيان موصوفين بوضوح كتوافق قديم، ولا يدخلان في قبول native |
| `--build` | تغليف AST والمفسّر في تنفيذي | يوثق كمسار تاريخي؛ لا يُحتسب ترجمة لغة إلى آلة |

بالتالي نجاح `--check` القديم ليس إثبات قبول المترجم الأصلي، ونجاح `--test` القديم ليس اختبارًا لبرنامجه الناتج. إصلاحهما له اختبارات CLI: برنامج صحيح نحويًا لكنه مرفوض نوعيًا يجب أن يفشل الفحص، وبرنامج تحقق يفشل يجب أن يعطي حالة خروج غير صفرية عبر ملف آلة فعلي. يجب أن يكون `--check` بلا آثار برنامج جانبية؛ غياب Clang يسمح بالفحص المستقل، لكنه يفشل البناء/الاختبار برسالة واضحة. حالات الخروج المقترحة: 0 للنجاح، 1 لفشل الفحص أو البناء أو الاختبار، 2 لوسائط CLI الخاطئة؛ يوثق أي ترميز مختلف قبل إصداره.

## بوابة إصدار native فقط

- [ ] مجموعة أمثلة مطابقة لكل بند لغة ومكتبة معلن، تُترجم وتُربط وتُشغّل؛ اختبارات رفض للبرامج غير المدعومة ورسائلها، واختبارات ارتداد للأوامر القديمة.
- [ ] فحص شكل الملف ومعماريته ورموزه واعتماداته، وتشغيله في بيئة لا تحتوي أداة لسان. فحص IR وحده أو غياب كلمة «Interpreter» منه وحده لا يثبت الاستقلال.
- [ ] لا استخدام `--interpret` أو `--build` أو `lisan::run` لتحقيق قبول native. مسموح runtime أصلي للذاكرة والنصوص وواجهات النظام، مع توثيق اعتماده؛ وجود libc لا يعني مفسّرًا.
- [ ] قياس الذاكرة والأخطاء العددية والحدود والنصوص العربية والدوال والوحدات؛ لا يُكتفى بنجاح مثال طباعة.
- [ ] هدف إطلاق أولي Linux x86_64 مستضاف، بإصدارات أدوات مثبتة في تقرير CI. Windows وmacOS وأي معمارية أخرى تضاف فقط بعد تقارير بناء وتشغيل خاصة بها؛ حزم المفسّر القديمة ليست دليلًا لها.
- [ ] سجل تحقق لكل إصدار يضم commit، ونظام التشغيل والمعمارية، وRust وClang والموصل، وأوامر البناء والاختبار ونتائجها. «تخطي لغياب الأدوات» حالة منفصلة وليست نجاحًا.

## مشاريع التوافق المنفصلة

| المشروع | حدود الالتزام | دليل القبول المطلوب |
|---|---|---|
| C/FFI | أنواع ABI وأغلفة معلنة؛ لا دعم تلقائي لـ C++ templates أو الأصناف | استدعاء دالة C حقيقية في ملف آلة مع فحص الحدود والتواقيع |
| Arduino | لوحة وcore وأداة ومكتبة بإصدارات محددة؛ أغلفة C للمكتبات C++ عند الحاجة | firmware صحيح ومعمارية وذاكرة صحيحتان، ثم Blink/UART على العتاد؛ البناء وحده موسوم build-only |
| المتصفح | wasm32 مع واجهة JavaScript موثقة للنصوص والذاكرة وDOM والأحداث | ملف wasm وصفحة واختبار في متصفح مسمى؛ WASI ليس إثبات دعم DOM |
| حزم خارجية | مكتبة بإصدار وهدف وواجهات مختبرة | اختبارات تكامل واعتمادات مقفلة؛ لا تعهد بـ«كل مكتبات Arduino أو الويب» |

راجع [مقترح العتاد والويب](superpowers/specs/2026-10-20-native-hardware-web-design.md) للتفاصيل المعمارية. لا يرفع مشروع التوافق حالة دعم اللغة على هدف لم يُختبر، ولا يمنع تأخره إعلان اكتمال النواة على هدفها المحدد.

## مراحل التنفيذ والإعلان

| المرحلة | المخرج | متى تُغلق؟ |
|---|---|---|
| 0.8.x | اتساق `--check` و`--test` والتوثيق والاختبارات الأصلية | أدلة CLI وبناء وتشغيل؛ دون إعلان اكتمال اللغة |
| 0.9 | واجهة أنواع مشتركة، دوال ومجموعات ووحدات وذاكرة وأخطاء بعقود منشورة | استيفاء بنود النواة واختبارات رفض وحدود |
| 1.0-rc | API مكتبة ثابت، حزم مقفلة، أدوات محرر وتقارير الهدف | تشغيل بوابة القبول كاملة وإصلاح العيوب المانعة |
| 1.0 | إصدار محدد الالتزام | تأشير جميع متطلبات 1.0 بأدلة؛ نشر المتبقي والمشاريع المستقلة بوضوح |

هذه مراحل ناتج وليست مواعيد أو نسب إنجاز. يجوز قياس النسبة داخل قائمة قبول مجمّدة ومعلنة فقط؛ لا تُستنتج «100% من اللغة» من عدد الملفات أو نجاح `cargo test`. تغيير العقد يتطلب إصدارًا جديدًا لهذه الوثيقة وشرح البنود المضافة أو المؤجلة.
